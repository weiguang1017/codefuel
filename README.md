## 特性

- **自动签到**：按账号设定间隔在后台执行，休眠或关机后的到期任务会在下次启动时补做。
- **自定义站点**：在「站点管理」配置接口与额度换算，复用账号授权、代理、定时任务和运行日志；内置站点保持两个。
- **来源真实**：签到结果严格区分 `success / already_checked / synced / manual_required / failed / interrupted`，不把"查询成功"当作"已领取额度"。
- **多种登录**：GitHub 授权、LinuxDO 授权、邮箱密码、已有 Session；授权过程中不接触你的密码。
- **本地优先**：只监听 `127.0.0.1`，凭据用 Fernet 加密后落在本机 SQLite，不上传任何服务器。
- **可追溯**：每次执行留存站点真实响应摘要，日志可导出 CSV（已做公式注入防护）。

## 自定义签到站点

1. 打开左侧「站点管理」→「添加自定义站点」，填写名称与 **HTTPS 根网址**，例如 `https://api.example.com`，不含 `/v1`、登录路径或查询参数。
2. 填完网址后，应用会自动探测并选择签到模式，同时匹配登录、余额与签到接口。无需先知道网站采用哪种系统；也可手动选择模式或展开「高级配置」。
3. 探测会读取 `/api/status`、`/api/v1/settings/public` 等公开信息，普通请求无法识别时尝试独立的无界面浏览器，不使用已保存的账号凭据或发起签到。可点击「重新检测」重试；手动修改过的配置不会被异步结果覆盖，也可明确点击「应用识别结果」。无法识别时会提示手动选择，仍允许按当前配置保存。编辑已有站点时只提供建议，不自动改写已有配置。
4. 保存后在站点卡片点击「添加账号」。该入口会固定目标站点，切换登录方式不会改选其他平台。自定义站点支持账号密码、浏览器手动登录、GitHub / LinuxDO 入口检测和已有登录态；New API 的账号密码方式允许用户名或邮箱，Sub2API 使用邮箱。遇验证码、二次验证或登录接口不兼容时，请改用浏览器手动登录。
5. 账号保存后，可使用单账号签到、签到全部及原有定时任务；每个账号仍独立配置代理。Session 过期或网站要求人工验证时，通过「重新授权登录」处理。

| 模板 | 默认签到方式 | 结果判断 |
|---|---|---|
| 标准 New API 签到 | `POST /api/user/checkin`，JSON 请求体 `{}` | 必须返回结构化 `success: true`，或明确的已签到信息 |
| Sub2API 签到 | `POST /api/v1/user/check-in` | 使用 Bearer 登录 Token，接受明确的 `code: 0` 签到回包，奖励读取 `data.reward` |
| AnyRouter 兼容签到 | `POST /api/user/sign_in`，JSON 请求体 `{}` | 支持 `success: true`，或没有 success 字段时的整数 `ret: 1` / `code: 0` |
| 仅同步余额 | 不发送签到请求 | 根据已识别的 New API / Sub2API 协议查询余额，只记为「已同步」，不计入已领取金额 |

列表统一为上述四项。旧版「Sub2API 仅同步余额」配置会显示为「仅同步余额」，原有 Token 登录方式和接口仍保留。切换到「仅同步余额」也会保留当前识别到的协议。

高级配置支持登录页、账号密码登录接口、签到接口、余额接口、用户标识请求头及额度单位。New API 默认使用 `POST /api/user/login` 登录和 `GET /api/user/self` 查询身份；请求头为 `new-api-user`，登录态是 `session` Cookie，用户接口需返回 `success: true` 和 `data.quota`、`data.used_quota` 等字段。

Sub2API 默认使用 `POST /api/v1/auth/login` 和 `GET /api/v1/auth/me`，登录态为本站 `auth_token`，不是调用模型的 API Key。浏览器授权后会在同源身份接口确认用户 ID，再将登录 Token、刷新 Token 加密保存。访问令牌过期时，后台尝试刷新一次，只有核对身份一致后才更新凭据。余额使用站点返回的 `balance` 原值；未提供的累计消耗不会伪造为零，签到奖励无法确认时显示未知。

对使用默认配置、尚无余额记录的新站点，应用会根据站点页面发布的配置识别 Sub2API（例如 LOXO），并保存正确模板。已有自定义接口、单位或余额记录时会提示手动选择模板，不覆盖这些设置。也可直接在「站点管理 → 编辑配置」选择 Sub2API 模板。LinuxDO 入口识别同时支持 `LinuxDO`、`Linux DO`、`Linux.do` 等写法；自动点击未打开授权页时，窗口会保留，供用户手动完成。

自定义站点的 LinuxDO 授权采用原生 Chrome。若完成人工登录或验证后停留于社区首页，可点击「继续原站点授权」，在同一浏览器资料中重新打开原站点并继续，保留本次 LinuxDO 登录状态。应用不在 LinuxDO 验证页连接驱动，也不把社区登录当成原站点登录；仍需完成原站点授权并通过本站身份接口校验后才保存。继续操作有次数限制，不自动反复重启验证。

账号授权及签到过程中，目标站点的「我已阅读并同意用户协议／隐私政策」复选框会自动勾选，支持原生和自绘复选框及延迟出现的表单。仅作用于当前站点，不勾选验证码、营销、付费或额外权限选项，也不自动提交注册或支付。用户在自动勾选后取消选择，不会被持续勾回。若默认 `/login` 返回 404，授权窗口会从站点首页的可见登录链接识别正确路径（例如 CUN.AI 的 `/sign-in`）并保存。

模板不执行任意脚本，也不支持任意响应字段映射；转盘、任务奖励、其他登录协议仍需专门适配。GitHub / LinuxDO 是否可登录、是否需要补充邮箱、邀请码或人工验证，由网站实际流程决定。

**额度展示**：显示值为原始 quota 除以换算值，默认 `500000`。可选择 USD、CNY 或本站积分；概览按单位切换，积分按站点独立统计，不自动进行汇率换算。日志与 CSV 保留执行时的单位。不同站点的额度也不代表相同的实际购买力。

**编辑与移除**：两个内置站点只读。自定义站点有关联账号后不能改网址，有账号或历史日志后不能改额度单位和换算；请新增站点并重新授权。签到、排队或授权期间禁止修改配置。移除站点前须先移除其账号；历史日志及所需站点名称仍保留，重启后不会重新出现在可选站点中。站点配置和账号凭据均保存在本机数据库，账号凭据继续加密。

## 同一个身份，连接多个平台

GitHub 和 LinuxDO 是登录身份，不绑定某一个签到平台。同一个身份可以分别登录所有**已适配、且实际提供对应登录入口**的平台；内置适配 AnyRouter 与 AgentRouter，自定义站点使用兼容模板并在登录时验证。

1. 添加账号时先选择「使用 GitHub 继续」或「使用 LinuxDO 继续」，再勾选一个或多个目标平台。
2. 码粮按选择顺序打开各平台的授权窗口；请在每个窗口使用你希望关联的同一个身份完成授权。
3. 每成功连接一个平台，账号列表中都会新增一条该平台的独立账号记录，可分别签到、查看余额和重新授权。
4. 已有 GitHub / LinuxDO 授权账号可通过「连接其他平台」继续添加平台，不必重复填写备注与登录方式。

**账号独立保存**：每个平台签发的 Cookie、站内用户 ID 均独立加密保存，不复制给其他平台，也不会仅凭相同备注或登录方式自动合并账号。应用不保存 GitHub / LinuxDO 密码。AgentRouter 授权时会将该账号的上游登录 Cookie 一并加密保存在本机，用于后台再次登录；不会共享给其他账号或平台。

授权窗口使用独立临时浏览器，不共享日常 Chrome 的登录状态；不需要提前在日常浏览器登录 LinuxDO，请在本次授权窗口里完成登录与授权。仅检测到 Cookie 不等于已登录，必须有本站有效身份响应才保存。

**AgentRouter 及自定义站点的 LinuxDO 授权**使用系统 Chrome 独立窗口：仅在原站点短暂连接，处理协议复选框并点击 LinuxDO 入口；开始进入 LinuxDO 时立即断开页面驱动，之后由本人完成登录、真人验证和授权。验证期间不注入页面脚本，也不修改浏览器标识；返回原站点后再连接以校验身份并保存。如果没有自动保存，可点击「已完成登录，检测并保存」。检测尚未通过时会断开驱动，保留窗口供继续操作，不反复请求身份接口。授权最多等待 15 分钟，结束或取消后关闭本次窗口并清理临时资料。同一账号仍使用已选择的代理；带认证的代理由 Chrome 显示认证框，需手动输入代理用户名和密码。

其他授权窗口会自动关闭普通公告、欢迎提示和明确的信息提示，验证码、密码及未经确认的权限请求仍需本人处理；没有站点主动响应时，应用按 8 秒、15 秒、之后每 30 秒的间隔核对身份，最多等待 15 分钟，也可点击「立即检测」。

如果登录响应已确认身份并签发匹配的 Session，余额接口暂时被拦截不会阻止保存授权。新账号余额显示未知，已有账号保留原余额，后续签到时再同步；登录回包的占位金额不会写入余额。

添加或编辑账号时，点击提交会将未填写或格式有误的字段标红，并自动滚动、聚焦到第一处错误。填写后提示自动消失，缺少必要信息时不会发起授权请求。

日常签到优先使用已保存的站点 Cookie，不退出已有会话，也不自动弹出授权窗口。AnyRouter 使用签到接口；AgentRouter 以登录响应的 `checked_in` 标记确认签到，余额始终从 `/api/user/self` 读取，普通余额查询只记为「已同步」。AgentRouter 旧账号若没有上游会话缓存，需要主动点击「重新授权登录」一次；后续在缓存有效时后台完成登录，遇到过期或网站验证则提示处理。登录响应中的占位金额、缺失字段和查询失败均不会覆盖已有余额，不能确认的奖励显示为未知。

AgentRouter 的自动登录流程会等待站点配置加载完成后才点击登录按钮，避免发出 `client_id=undefined` 的无效授权请求。GitHub 和 LinuxDO 日常签到统一使用无界面 Chrome，不弹窗、不抢焦点，并在应用运行期间按账号复用同一会话；确认授权页对应当前 AgentRouter 请求后自动点击「允许」。只有主动添加账号或重新授权才打开登录窗口。退出应用或删除账号会关闭对应的后台浏览器。完整的前后余额均已取得且总额度相同时，本次新增金额记录为 `$0.00`。

LinuxDO 后台登录会恢复授权时的 Chrome User-Agent，并随该账号的 Cookie 一同加密保存；旧账号自动根据本机 Chrome 补齐，避免切换为无界面模式后因浏览器标识变化而出现 403。无界面模式仍能处理网页弹窗：自动关闭 AgentRouter、LinuxDO 官方页面的普通公告与欢迎提示（含延迟显示的提示），并支持官方「允许」链接及授权表单按钮。验证码、登录表单、权限提示不会被当作公告关闭；站点明确要求人工验证时仍需主动重新授权处理。

人工授权窗口保留系统 Chrome 的原生 User-Agent 和 Client Hints，不应用后台登录的兼容覆盖。LinuxDO 尚停留在登录、SSO 或真人验证页面时，不主动请求目标平台账号接口。恢复 Cookie 时保留分区信息，避免同名 Cookie 被合并覆盖。网站的真人验证仍需用户完成；如果普通 Chrome 窗口也持续循环，应先取消授权并检查该账号选用的网络或代理。

AgentRouter 会对连接阶段、后台授权阶段的临时网络中断、页面加载超时或 HTTP 408 / 5xx 分别自动重试最多 2 次，间隔为 2 秒、5 秒；授权配置暂未加载也会重试。重试计入同一条运行记录。已确认签到后不重复登录；登录请求已发出但结果不明时停止自动重试，保留已有余额和凭据。明确要求重新登录、人机验证、HTTP 403 / 429 等情况停止自动登录重试并提示处理，不自动切换为可见窗口。

AnyRouter 首次登录页若未显示第三方入口，应用会尝试点击站内「注册 → 登录」链接，再查找对应授权按钮；该过程只导航页面，不填写或提交注册信息。AgentRouter 继续直接使用现有登录入口，不走这段导航。

如果当前页面仍未显示可识别的入口，本次授权会明确提示未完成，而非断言平台完全不支持；你可以重试或跳过该平台继续连接其他平台。取消剩余授权不会删除已成功添加的账号。邮箱密码与手动 Session Cookie 仍一次添加一个平台。

> 平台是否开放 GitHub / LinuxDO 登录，以实际登录页为准；“已适配”不等于保证该平台当前启用所有登录方式。跨平台连接不代表登录一次即可自动获得所有平台的授权或额度。

## 每个账号独立配置代理

添加或编辑账号时，在「网络代理」中选择：

- **默认网络**：沿用平台原有行为。AgentRouter 使用配置好的 `CHECKIN_PROXY_URL` 环境代理，未配置时直连；AnyRouter 默认直连。
- **直连**：该账号明确不使用代理。
- **自定义代理**：填写完整地址，例如 `http://127.0.0.1:7890`、`https://proxy.example:8443` 或 `socks5://127.0.0.1:1080`。HTTP/HTTPS 可单独填写用户名与密码；系统 Chrome 的 SOCKS5 连接仅支持无认证。

同一账号的首次授权、重新授权、后台登录、余额查询和手动/定时签到共用这份配置；一次选择多个平台时，各平台账号分别保存表单中的代理设置。代理不可用时会报告失败，不会自动切换为直连。

地址与认证信息加密保存在该账号的凭据中。编辑时不回显用户名和密码，地址不变时留空可保留原认证；修改地址后需重新填写，取消认证勾选可清除认证。修改代理会关闭该账号缓存的后台浏览器，下一次任务按新配置连接。切换网络出口后，网站可能要求重新授权。

### 常用自检

```bash
uv run desktop.py --selftest          # 仅启动本地服务，不打开窗口
uv run desktop.py --browser-selftest  # 用本地页面验证浏览器驱动，不联网
uv run desktop.py --smoke             # 打开真实窗口读取页面后退出
```

多平台界面回归使用本机 Chrome 和仅监听 `127.0.0.1` 的临时静态服务，覆盖逐平台授权、部分失败、取消、重试与认证方式切换。运行会写入账号的旧版 `tests/ui_check.py` 时，必须显式指定隔离的 `CODEFUEL_DATA_DIR` 与本地测试服务 `CODEFUEL_TEST_URL`，不要指向日常使用的数据或服务。

## 打包

```bash
bash build/build_macos.sh        # macOS：产出 .app、.dmg（使用当前 Mac 架构）
build\build_windows.bat          # Windows：产出 dist\CodeFuel\CodeFuel.exe
```

推送 `v*` 标签会触发 GitHub Actions 自动构建两个平台的安装包并发布 Release。

应用左下角的版本号由后端统一提供。发布构建使用触发发布的 Git tag（例如 `v1.2.3`），构建时将其写入安装包中的版本信息文件，避免发新版本时遗漏修改界面。指定的发布 tag 必须指向当前检出的提交，否则停止构建。

本地源码运行或构建默认使用当前提交最近的 `v*` 版本 tag；没有可用 Git tag 的源码目录才回退到 `pyproject.toml` 中的版本。安装后的应用只读取打包时固定的版本，不受运行目录或本机 Git 仓库影响。两个内置站点和自定义站点均可直接使用，之前被会员预览功能暂停的账号会在启动时恢复普通签到状态。

从旧版本升级时，`DailyQuota` 目录下的数据库与密钥会在首次启动自动复制过来，旧数据保留不删。也可用环境变量 `CODEFUEL_DATA_DIR` 指定其它位置。
