# VIP 微信支付历史规划（暂不启用）

## 历史方案

| 套餐 | 价格 | 权益 |
|---|---:|---|
| 月付 | ¥3.90 | 1 个月 VIP |
| 年付 | ¥30.00 | 1 年 VIP |
| 终身 | ¥50.00 | 长期 VIP |

以下为之前讨论的 VIP 方案，仅作后续参考。目前内置与自定义站点均可直接使用，没有会员限制。

## 当前版本能做什么

VIP 展示、支付占位接口和权限限制已移除，也未接入真实支付或采集设备指纹。本清单仅保留未来如需恢复支付时的准备事项。

## 你需要准备的资料

| 资料 | 用途 | 如何提供 |
|---|---|---|
| 已开通 Native 支付的微信支付商户号（mchid） | 桌面端展示二维码，用户用微信扫码付款 | 商户号及开通状态 |
| 与商户号关联、可用于该支付业务的 AppID | 下单时识别支付应用 | AppID 和关联状态 |
| 商户 API 私钥及对应商户 API 证书序列号 | 服务端为微信支付请求签名 | 受限配置文件的本地路径；私钥不发到聊天、不提交 Git |
| API v3 密钥 | 解密支付成功回调 | 放在受限配置文件或服务器密钥管理中，提供配置位置 |
| 微信支付公钥、公钥 ID（或所选平台证书方案） | 校验微信支付响应和回调签名 | 商户平台取得的文件与标识；接入时统一确认验签模式 |
| 一个公网 HTTPS 域名 | 桌面端访问会员服务、微信支付回调 | 域名及 DNS / HTTPS 是否已配置 |
| 可部署后端的服务器或容器环境 | 保存订单、权益并处理回调 | 服务器 / 项目位置、部署方式及数据库条件 |

商户私钥和 API v3 密钥只能部署在服务端。桌面安装包只配置会员服务地址，不能携带商户支付密钥。

暂时不必先建回调接口；提供域名和服务器后，再确定正式路径。下单 API 的 `notify_url` 会指向该公网回调地址。

## 上线前还要确定的运营规则

- 月付、年付按自然月 / 自然年计算，还是固定 30 / 365 天；套餐到期前再次购买时如何累加。
- 重装系统或更换电脑时，是否允许迁移 VIP，以及人工核验方式。
- 退款政策；退款成功后立即撤销还是按剩余时长调整权益。
- VIP 核验服务暂时不可达时的处理方式及可接受的核验缓存时长。

## 配置就绪后的接入工作

1. 建立订单与会员数据库，价格以服务端配置为准，不能由客户端提交金额决定。
2. 接入微信 Native 下单和二维码展示，客户端轮询本机订单的结果。
3. 对支付回调验签、解密，核对商户、AppID、订单号、金额和币种后开通权益；重复通知不能重复延长有效期。
4. 支持主动查询订单补偿、到期核验、续费、终身权益和退款处理。
5. 接入本机绑定与服务端 VIP 核验，完成真实小额支付、回调、退款及失效恢复验证后再开放支付入口。
